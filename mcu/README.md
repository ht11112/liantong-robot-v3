# 联通 V3 底盘 MCU

此目录给 STM32G474 提供串口速度控制和实测轮式里程计。采用联通现有板级接线，软件命令行为参考树莓派小车。构建和测试均离线。

## 串口与运动

- LPUART1 为 115200 8N1，PC1 TX、PC0 RX、PB1 高有效 RS485 DE。RK 是唯一主站，一请求一应答。完整请求后按毫秒 tick 的 2 ms RX 安静窗口调度回复，物理最小转向时间待实测。上电和空闲不主动发帧。命令接受 CR 或 LF，CRLF 只处理一次。
- `CMD,v,w` 或裸 `v,w` 接受有限数，两个分量分别限制在 ±1，再按 m/s、rad/s 换算成轮速。解析保留 `strtod` 的数值前缀、尾字忽略和无转换为零，例如 `CMD,0.18,abc` 是 0.18 m/s、0 rad/s，`foo,0` 是零目标。完整控制字才执行，坏的保留字前缀、超长行和非有限数返回 `ERR,INPUT`。UART 错误放弃当前行，从下一个行边界恢复。
- `STOP` / `ESTOP` 清目标并锁存，`RESUME` / `START` 解锁并保持零目标。锁存或 CAN 故障期间，合法 CMD 仍返回解析 ACK，给定不保存。恢复健康之后需新 CMD。
- 最后一条被采用的命令经过 510 ms 后清目标，依次请求零给定、驱动 Quick Stop，无应用 STOP 锁存。Pi 原源码在 10 ms 时基的第 51 个 tick 触发，实际相位约 500–510 ms；V3 按接收命令的 MCU 毫秒时钟计 510 ms。QUERY 不刷新命令时间。ACK 说明命令已解析，无法证明电机停稳。

## CANopen 与里程计

- FDCAN3 PB3/PB4，经典 CAN 500 kbit/s，标准 ID `0x601` 请求、`0x581` 应答。启动尝试写零，读取实际速度模式 `0x6061:00=3`、双轴配置 `0x200f:00=1`、给定单位 `0x2026:05=1`。第一次有效非零给定之前，控制字 `0x6040` 依次写 6、7、15，核对双轴状态字低位 1、3、7。
- `0x60FF:03` 低 16 位是左轮、高 16 位是右轮，单位整数 RPM，前进左正右负。驱动原有参数保持现场配置。软件只按目标字段有符号表示范围饱和。Quick Stop 使用联通已测过的 `0x6040=2`，物理行为取决于驱动器与其减速配置。
- 同时只有一笔 CAN SDO 在途，应答窗口 50 ms。发送失败、超时、应答异常或配置不匹配会清目标，使里程计无效并进入停车处理。零给定或 Quick Stop 有限等待应答，失败后间隔至少 50 ms 再试；确认零与快停前暂缓普通 CAN 轮询。CAN 恢复后需重新核驱动配置、收到真轮速，再由新 CMD 恢复控制。硬件 bus-off 保持时没有 CAN 发送，须恢复总线并重新启动 MCU，随后重新建立 RK 定位会话。
- CAN 故障码为 `0` 无故障、`1` 发送失败、`2` 超时、`3` SDO 应答异常、`4` 驱动配置或使能状态不匹配、`5` FDCAN bus-off。总线不通时软件无法核实停车是否送达。CANopen SDO 无事务序号，同一对象的异常晚到应答存在归属限制。
- 正常约每 50 ms 从 `0x606C:03` 读真轮速，两侧有符号值均为 0.1 RPM。用当前标称轮径 0.20 m、轮距 0.30 m 和 SDO 回包完成 tick 做累计积分。源断开或测量间隔达到 150 ms 时停止跨段积分，新的有效样本重新建立区间。QUERY 返回 boot、真实样本序号、测量和回包 tick、有效性、积分段、累计姿态和速度。反馈仍待实地标定，真反馈的采样时间是 MCU 收到 CAN 回包时刻。

## 离线构建

```text
python -B mcu/build.py --host-tests --firmware --name v3-check
```

主机测试编译生产 C，使用系统 C 编译器或现有 Unity Emscripten，并以固定 CAN 对端供给实际字节响应。ARM 构建使用现有 STM32CubeG4 1.6.3 和 STM32 GNU Tools，32 KiB 应用区，4 KiB 栈，Cortex-M4F 硬件单精度与 LTO。工具路径可通过 `--sdk`、`--compiler-dir` 和 `--emscripten` 指定。结果保存在 `build/<name>`，包含 BIN、ELF、map、C 测试日志和源码及工具哈希收据。测试不连接串口或实物，板级时序和停车效果须另做实机验证。
