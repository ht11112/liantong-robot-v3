# V3 文本协议

这是适配联通 G474/CAN 双轮驱动器的新协议，使用树莓派参考程序的速度与 STOP/RESUME 概念。它不兼容 V9/V10/V11/V12 二进制客户端，也不能直接使用附件原串口桥。仓库名和线上实现统一称 V3，避免与现有二进制 V11 混淆。

## 线路与事务

- RS485，115200 baud，8 数据位、无校验、1 停止位。RK 是唯一主站和唯一串口持有者。
- 一次发送一条请求，读完对应的一行回复再发下一条。MCU 不主动输出启动提示或周期反馈。
- 接收 CR 或 LF，CRLF 只执行一次。MCU 按毫秒 tick 的 2 ms 接收安静窗口调度回复，实际收发方向切换由硬件 DE 完成；物理最小转向时间尚未实测。
- RK 默认每 50 ms 开始一个查询周期；启用运动时在查询应答后插入最多一个控制事务。慢事务不积压补发。
- RK 读/写超时为 100 ms；协议错误或串口错误结束 ROS 桥，不自动重试或重放旧命令。该数值未经本版本实测验证。
- 没有 CRC、请求序号、任务号、租约或自动应答重试。半双工时序和硬件误码仍需后续单独验证。

## 命令

| 请求 | 回复 | 行为 |
| --- | --- | --- |
| `QUERY` | 一行 `ODO,...` | 查询当前测量；不延长速度命令寿命 |
| `CMD,0.10,0.20` | `ACK,CMD` | `v=0.10 m/s`、`w=0.20 rad/s` |
| `0.10,0.20` | `ACK,CMD` | 裸双数值兼容入口 |
| `STOP` / `ESTOP` | `ACK,STOP` | 清速度目标，请求驱动停车，设置软件停止锁存 |
| `RESUME` / `START` | `ACK,RESUME` | 清停止锁存和速度目标；必须再收到新 CMD 才运动 |
| 不支持的命令、过长或非有限数值 | `ERR,INPUT` | 丢弃本行，不更新目标或命令时刻 |

命令词不区分大小写，完整匹配。保留命令词的错误前缀/后缀不当作裸数值，例如 `STOP,0.2` 和 `CMDX,0.2` 被拒绝。宽松数值解析保留：`CMD,0.18,abc` 的角速度是零，普通裸 `abc,0.2` 的线速度是零，数值后尾随文本按 `strtod` 行为处理。NaN/Inf 被拒绝；两个分量分别限制在 ±1。±1 是参考协议边界，不是标定结果或现场推荐速度。

显式 STOP 锁存或驱动故障期间的 CMD 可以收到解析 ACK，但不会成为可执行的运动目标。ACK 不表示电机已经响应或车辆实测停稳。

正常命令龄达到 510 ms 后清零并请求驱动停车，不设置 STOP 锁存；后续新 CMD 可恢复。RK 的 `/cmd_vel` 缓存默认只新鲜 0.3 s，过期后停止发送 CMD、继续 QUERY。因此从最后一条 ROS 速度消息到 MCU 超时停车的上限还包含缓存时间和串口调度，不能宣称为固定 510 ms，更不等于机械停止距离。

## ODO：14 个逗号分隔字段

```text
ODO,boot,seq,measurement_ms,reply_ms,valid,segment,x,y,yaw,v,w,stop_latched,fault
```

| 字段 | 类型/单位 | 定义 |
| --- | --- | --- |
| `boot` | 16 位十六进制字符串 | 本次 MCU 启动身份，来自硬件 RNG |
| `seq` | uint32 | 每次真实 CAN 轮速回包递增，重复 QUERY 不增加 |
| `measurement_ms` | uint32，ms | MCU 收到该次 CAN 轮速回包的时刻；不是驱动器内部 ADC/编码器硬件采样时刻 |
| `reply_ms` | uint32，ms | MCU 形成本次串口回复的时刻 |
| `valid` | 0/1 | 有有效真实轮速测量、未发生使其失效的故障且源龄小于 150 ms |
| `segment` | uint32 | 连续积分段；故障/缺样打断已有效里程计时改变 |
| `x,y` | m | MCU 累计局部里程计位置 |
| `yaw` | rad | 累计旋转后的朝向，归一化至 ±π；标定整圈需展开角度 |
| `v,w` | m/s、rad/s | 最新实测轮速换算的车体速度 |
| `stop_latched` | 0/1 | 显式 STOP 软件锁存，不是实测停车证明 |
| `fault` | uint32 | 当前驱动通信/配置故障，见下表 |

计数器差值按 uint32 回绕计算。反馈无效时返回现有快照并标记 `valid=0`；不能把其中的位姿或速度当成新测量。恢复时不跨缺失区间积分，ROS 定位会话必须处理 `segment` 变化。

| fault | 含义 |
| --- | --- |
| 0 | 未报告驱动故障 |
| 1 | CAN 发送失败 |
| 2 | CAN 应答/测量超时 |
| 3 | CAN SDO abort 或不符合约定的应答 |
| 4 | 驱动模式、单位或使能状态不符合当前适配 |
| 5 | CAN bus-off |

## ROS 时间与坐标

首次有效样本以 `RK 请求开始单调时刻 - uint32(reply_ms - measurement_ms)` 为保守时间锚；后续用真实 MCU 测量 tick 的增量推进，避免每条 USB 应答延迟改变测量间隔。同一源样本只发布一次 `/odom` 和 `odom→base_link`，二者时间戳完全一致。该映射不是硬件同步，MCU 晶振漂移和链路延迟应在标定时量测。

无效或重复反馈不发布新里程计。已发布后启动身份或连续段变化，结束本次 ROS 定位会话，重新启动后重新设置 `/initialpose`。这避免旧 TF 插值跨越重启或缺失运动；不会给 MCU 增加 V12 式永久锁存。

`map→odom` 只由持续 AMCL 发布；`base_link→laser` 是实际安装外参；`/initialpose` 只设定地图位置，不清 MCU odom。雷达保留原测量时间，裁剪扫描后时间戳按保留的第一束修正，不用收到消息的当前时间替代。
