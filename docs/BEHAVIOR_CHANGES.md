# V3 行为变更

V3 是独立的 G474 固件和 RK ROS1 程序。底盘接收即时差速速度，RK 使用已有地图和持续运行的 AMCL，并提供可选的 ROS 导航入口。以下以附件中实际执行的 STM32 和 `miiboo_nav` 链路，以及联通 V12 队列程序为比较对象。

## 下位机

| 项目 | 树莓派附件 | 联通 V12 | 联通 V3 |
| --- | --- | --- | --- |
| 速度入口 | `CMD,v,w` 或裸 `v,w`。分别限幅至 ±1，再用 `800`、`-800` 转成内部量，10 ms 编码器 PI 直接控制 PWM | 上传 MOVE/TURN 队列，显式 START 后由 MCU 执行 | 保留两种速度报文和分量 ±1 限幅。`v` 用 m/s，`w` 用 rad/s，按本车几何换算 CAN 双轮目标 |
| 正常停走 | `STOP` 或 `ESTOP` 清目标、短刹车并锁存。`START` 或 `RESUME` 解除锁存，STOP 后须收到新速度才动 | STOP 废弃当前队列。新运动须重新上传并 START | `STOP` 或 `ESTOP` 清目标、请求驱动停车并锁存。`START` 或 `RESUME` 解除锁存，下一次行驶取新速度 |
| 命令断流 | 超过 50 个 10 ms tick 清目标、短刹车。普通超时无锁存，下一条速度可恢复 | MCU 任务和续约机制管理已下发动作 | 命令龄达到 510 ms 后清目标，等效于参考车的第 51 个 10 ms tick。下一条速度可恢复，显式 STOP 锁存另计 |
| 串口与反馈 | 115200 8N1 TTL。主动约 20 Hz 发旧格式 `ODO`，速度命令回显整数 | 半双工二进制通信，使用任务、身份和应答规则 | 115200 8N1 半双工 RS485。单请求单应答，完整请求后留 2 ms 安静间隔，`QUERY` 返回 `ODO`，其余返回对应 ACK 或输入错误 |
| 里程计 | 读硬件编码器增量后积分。报文无样本有效性标志，源码把航向写成单周期角增量 | MCU 累计里程计用于执行队列 | MCU 用真实 CAN 轮速累计位姿和航向，报告 boot、样本序号、接收轮速和应答 tick、有效性、连续段与驱动故障。源龄达到 150 ms 时反馈无效 |
| 驱动故障 | TB6612 由 PWM 直接驱动，串口接收实现无独立 UART 故障锁存 | UART 和驱动异常可进入故障锁存，另有任务约束和硬件 IWDG | CAN 通信超时等可恢复故障会清目标，尝试零目标和 Quick Stop，恢复后须收到新 CMD。CAN bus-off 会清目标并停止 CAN 发送，排除故障后需重启 MCU 和定位。V3 取消 V12 的永久 UART 故障锁存、队列、续约、IWDG 和 5 RPM 目标上限 |

输入保留附件宽松的数字解释，例如第二个速度字段 `abc` 解释为零。V3 按完整命令词识别 `STOP`、`START` 等指令，拒绝 NaN、Inf 和超长行，超长行的剩余字节丢弃至行结束。接收期检测到串口错误时丢弃受损行。锁存或 CAN 故障时，合法 CMD 仍可获得解析 ACK，但不会写入速度目标。完整线格式和 ACK 文本见 [线协议](PROTOCOL.md)。

树莓派程序的短刹车作用于 TB6612，V3 的零目标与 Quick Stop 作用于 CAN 驱动器。ACK 确认命令已被处理，实际停车时间和停稳需结合驱动反馈及现场观察。断开 CAN 时，MCU 发出的停车命令无法抵达驱动器。驱动器自身掉线保护由实际驱动器配置决定，本轮没有核验。

## RK ROS 桥与定位

| 项目 | 树莓派附件 | 联通 V12 | 联通 V3 |
| --- | --- | --- | --- |
| 速度与默认模式 | `/cmd_vel` 回调直接写串口，并对近似直行施加固定配平 | 网页任务转换为动作队列 | 桥默认只发 `QUERY`。显式 `enable_motion` 后启用速度和 STOP/RESUME。缓存速度超过 0.3 s 后停止续发，只查询，等待 MCU 自身的超时停车 |
| `/odom` 与 TF | 串口桥从旧 `ODO` 只取 v/w，乘 `.043` 和 `.040`，以 50 Hz 重积分。串口断流后沿用旧速度，并用当前时间发布 | 使用 MCU 反馈历史配对雷达和里程计，供本地避障和路线判定 | 使用 MCU 累计的 SI 位姿与速度。同一有效新样本的 `/odom` 和 `odom→base_link` 共用源时间。重复序号、无效反馈和断流不会刷新位姿 |
| 会话变化 | 串口桥首次打开失败或后续通信异常均无自动重连，后续读异常被吞掉 | 新 MCU 会话影响原任务及定位身份 | 串口错误退出。已发布里程计后，boot 或连续段变化结束本次定位会话，需重新启动。旧速度缓存不会自动恢复 |
| 雷达和 AMCL | 主入口用 LD14P `/scan`，`map_server` 和 AMCL。跟踪脚本分别读取最近一次扫描和位姿，无时间配对 | RK 避障先在真实里程计历史内为扫描找时间括号，再投影到地图坐标 | 保留原扫描时间基准，按保留的首个光束调整时间戳和角度。前 180°、距离至少 1 m 的观测供 AMCL 使用。AMCL 在取得有效扫描与位姿后发布唯一的 `map→odom`，桥发布 `odom→base_link`，雷达节点发布配置的静态外参 |
| 路径执行 | GlobalPlanner 产出路径，PC 自写跟踪器发布实际速度 | RK 规划动作队列和自动绕行，网页发起任务 | `localization.launch` 仅启动定位链。可选 `navigation.launch` 使用标准 `move_base`、GlobalPlanner 和 DWA。只有显式启用运动后，桥才转发 `/cmd_vel` |

V3 在首次有效样本用 RK 发出查询的单调时刻减去 MCU 应答 tick 与测量 tick 的差值，作为保守时间锚。后续按 MCU 测量 tick 增量推进 ROS 时间戳，减少串口应答抖动对间隔的影响。两边没有硬件时钟同步，漂移和链路延迟需按 [标定与验收](CALIBRATION.md) 测量。

DWA 的配置限速作用于 `move_base` 产生的速度。其他 `/cmd_vel` 发布者的指令仍按 MCU 的分量限幅执行。CAN 目标量化为整数 RPM，驱动器反馈分辨率为 0.1 RPM。特别低的速度可能量化为零，实际低速和转向应在场地标定。当前交付为离线实现，未据此验收停车、标定、地图重定位或行驶性能。
