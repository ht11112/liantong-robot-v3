# 标定与验收

本页用于后续在联通实车上验证 V3。本文的距离、次数和误差界是建议的首轮验收标准。发布包的离线检查无法给出实际停车、里程计或地图定位精度。标定使用本机和 RK 已有的 ROS1 诊断命令、RViz、卷尺和地面标记。场地地图与原始日志保留在本地。

## 反馈时间和坐标系

1. 先在车辆停稳、桥仅发 `QUERY` 时检查通信。持续记录 60 s 的发送和应答时间、`boot`、`segment`、`seq`、`measurement_ms`、`reply_ms`、`valid`，以及雷达原始 `header.stamp`。分别统计请求往返时间、真实新样本频率、重复、失效和连续段变化。桥目标约 20 Hz，CAN 采样约 50 ms，查询数和真实样本数分别统计。
2. 用 uint32 模运算求 `age_ms = (reply_ms - measurement_ms) mod 2^32`。首次有效样本以 `query_send_monotonic - age_ms/1000` 为保守时间锚，后续按 MCU 测量 tick 的增量推进。`measurement_ms` 对应 MCU 收到轮速回包的时间。同一有效样本的 `/odom` 与 `odom→base_link` 时间必须一致，新样本时间应严格前进。量出原始雷达扫描的接收年龄，用 RViz 或 `rosrun tf tf_monitor` 核对是否有对应时刻的 TF，并比较较长观察中 MCU tick 增量和 RK 单调时钟增量，记录实际漂移。
3. 用 `rostopic hz`、`rostopic echo` 和 TF 工具分别核对 `/odom`、原始雷达与裁剪雷达。裁剪保留从原始索引 `first` 开始的光束时，新时间戳应为 `raw_stamp + first × time_increment`，新起始角为 `raw_angle_min + first × angle_increment`。一起核对步长和距离数组，使同一回波仍落在同一方向。统计 AMCL 消费扫描时是否有对应 TF。
4. 静止首轮建议 60 s 内无通信超时或无效反馈，样本时间无回退，AMCL 无持续 TF 外推错误。重复查询同一 `seq` 时应无新的 `/odom`。串口断流应停止新位姿发布。MCU 重启或连续段变化后，重新启动定位并用当前位姿初始化，检查新会话从新的身份开始。

## 左右轮符号、有效轮径和轮距

1. 核实待标定版本和 [轮径、轮距配置](../mcu/include/control.h)。在已有的架空或低速空地试验流程中，先分别给小幅前进、后退和左右原地转向。以 `base_link` 为准，车头前进是 +x，从上方看左转是正 yaw。先比对实物轮向、编码器方向和 `/odom`，再拟合几何参数。
2. 在平直地面量取相距约 2 m 的两点，从相同参考点起步和停车。双方向各做至少 3 次，记卷尺位移与同一 `boot`、`segment` 中的里程计位移。共同有效轮径可按 `D_new = D_old × |d_reference| / |d_odom|` 估计。若已知编码器每轮整圈计数 `N`，可用轮转圈数 `n = Δcount / N` 交叉检查，直行的单轮估计为 `D = |d_reference| / (π × |n|)`。驱动器原生位置计数应先核单位、符号和传动比。
3. 固定轮径后，在地上标记初始朝向。顺、逆时针各做至少 3 次 360° 低速转向，累计解包 `/odom` 航向变化，比较实际转角。有效轮距估计为 `b_new = b_old × |θ_odom| / |θ_reference|`，或在左右轮位移可信时用 `b = (s_right - s_left) / θ_reference`。直行与转向应分别拟合，按中位数选参数，再用不同距离和转角复核。
4. 独立复测建议把 2 m 直线的里程误差控制在 5 cm 内，单圈角误差控制在 5° 内。出现反向误差、直线明显漂移或重复性差时，先查轮向、轮胎接地和打滑，记录实际散布后再决定是否能用一组参数。轮式里程计试验使用 `/odom`，避免 AMCL 的地图校正掩盖轮式误差。

差速约定为 `v_left = v - w × b/2`、`v_right = v + w × b/2`，线速度换算为 `rpm = 60 × v_wheel / (π × D)`。驱动器安装方向的符号换算独立核对。V3 要求 CAN 给定分辨率为 1 RPM，实测轮速分辨率为 0.1 RPM。按默认轮径 0.20 m、轮距 0.30 m，约 0.035 rad/s 的纯转指令才达到每轮半个 RPM 的量化门槛。记录实际低速起转点和反馈，不用规划器指令值推断实物已经运动。附件树莓派的 800 倍内部指令、固定配平和 `.043`、`.040` 缩放属于其旧底盘，V3 的几何标定以联通实物和 SI 单位为准。

## 雷达安装与地图定位

1. 以轮轴中点的 `base_link` 为参考，量取雷达测量中心的前后、左右、高度和偏航，分别设为 launch 的 `laser_x`、`laser_y`、`laser_z` 和 `laser_yaw`。核对原始扫描方向和裁剪节点输出 `/scan` 的 `frame_id=laser`，让 `base_link→laser` 与 AMCL 使用的坐标系对应。保留这一条外参的唯一发布者。
2. 让车辆分别面向一面平墙、沿墙平行停车，在有效量程内至少选两个距离。RViz 中把激光投影到 `base_link`，核对直墙方向、墙距和左右方向，再在低速原地转动时观察静态墙面。固定偏移或镜像优先核查外参与角度方向，随转向速度增大的偏差再查扫描与里程计时间。裁剪只留下车头前方 180°，1 m 以内按当前策略无可用测量，检查图中这部分的含义与原数据一致。
3. 以本地 YAML 和 PGM 加载同一张已知地图。保留分辨率、原点与占用阈值，在多个已知起点对比墙角和走廊。用 RViz `2D Pose Estimate` 给出初始位姿，观察 `/amcl_pose` 收敛以及 `map→odom→base_link` 是否完整。随后在两个非对称位置重做，并检查重新初始化后仍只有 AMCL 发布 `map→odom`。
4. 场地允许时，低速经过有墙角和长墙的短闭环，比较出发、返回位置与方向，记录 `/odom` 漂移和 AMCL 回到已知点的误差。首轮建议至少三次，分别记录地面标记误差、AMCL 最终误差和收敛时间。用不同初始位置区分参数偏差与地图对称导致的误定位。

## 停车和恢复

低速测试前先验证静止通信、轮向和地图坐标。实车验收分别测停止发布 `CMD` 与显式 `STOP`。记录最后一个有效速度、MCU 超时或 STOP 应答、实际零目标及实测零速的时间。普通断流在 MCU 最后收到速度 510 ms 后请求停车，RK 速度缓存还会影响从上游停发到 MCU 停车的总时间。恢复的第一条速度应为新指令。显式 STOP 之后先验证速度不生效，再发 RESUME 和新速度。将 CAN 失效、驱动恢复、零目标和 Quick Stop 的实际行为单独记录。CAN bus-off 需要排除故障后重启 MCU 和定位，断开 CAN 时的驱动器自身保护另行实测。

只有经过各项实机测量，才能据此给出可用的轮径、轮距、外参、定位误差和停车时间。离线测试和静止观察的结果分开登记。
